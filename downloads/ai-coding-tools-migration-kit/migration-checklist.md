# AI 编程工具切换检查清单

## 切换前：盘点当前工具

### 配置与账号
- [ ] 记录当前工具的订阅类型和到期时间
- [ ] 导出账号设置、快捷键和偏好配置
- [ ] 确认是否有团队/组织级配置需要迁移
- [ ] 记录当前工具的 API 密钥和模型选择（如有）

### 自定义规则
- [ ] 导出项目级规则文件（如 `.cursorrules`、`.copilot-instructions.md`）
- [ ] 记录全局自定义提示词和代码风格约定
- [ ] 检查是否有团队共享的规则集需要保留
- [ ] 确认这些规则在目标工具中的对应配置方式

### 项目上下文
- [ ] 列出当前工具索引的项目目录
- [ ] 记录常用的工作区和多项目配置
- [ ] 检查是否有项目级忽略规则（哪些文件不被 AI 读取）
- [ ] 确认敏感文件（.env、密钥、证书）是否已正确排除

### 历史与记忆
- [ ] 导出常用对话/会话历史（如工具支持）
- [ ] 记录常用的代码片段和模板
- [ ] 检查是否有工具学习的个人编码习惯需要重新建立
- [ ] 确认是否有团队共享的知识库需要迁移

## 切换中：评估候选工具

### 基础能力测试
- [ ] 用同一组 5 个代码补全任务测试每个候选工具
- [ ] 测试代码解释能力（给一段复杂代码，看解释是否准确）
- [ ] 测试 Bug 修复能力（给一个有 Bug 的函数，看能否定位并修复）
- [ ] 测试重构建议（给一段可优化的代码，看建议是否合理）
- [ ] 测试多文件理解（给一个项目中的多个文件，看能否理解关联）

### Agent 能力测试（如需要）
- [ ] 测试终端命令生成和执行能力
- [ ] 测试多步骤任务完成能力（如"给这个项目加一个单元测试"）
- [ ] 测试文件读写和项目结构理解
- [ ] 测试错误恢复能力（Agent 出错后能否自我纠正）
- [ ] 测试长任务的稳定性和上下文保持

### 集成与工作流
- [ ] 确认目标工具支持你的 IDE/编辑器
- [ ] 测试 Git 集成（提交信息生成、代码审查）
- [ ] 测试调试器集成（能否读取断点和变量）
- [ ] 确认团队协作功能（如共享规则、代码审查）
- [ ] 测试离线/低网络环境下的可用性

### 成本与合规
- [ ] 计算预期用量下的月度成本
- [ ] 确认数据隐私政策（代码是否会被用于训练）
- [ ] 检查企业/团队合规要求（如数据驻留、审计日志）
- [ ] 确认是否有教育优惠或开源项目免费额度
- [ ] 对比免费额度是否满足日常使用

## 切换后：稳定运行

### 配置迁移
- [ ] 在新工具中导入自定义规则和代码风格
- [ ] 重新配置项目索引和忽略规则
- [ ] 设置常用快捷键和界面偏好
- [ ] 配置模型选择和用量限制
- [ ] 连接必要的 MCP 工具和外部服务

### 工作流验证
- [ ] 用真实项目完成一天的日常开发，记录痛点
- [ ] 确认代码补全质量满足预期
- [ ] 确认 Agent 任务完成质量满足预期
- [ ] 测试团队协作场景（如 PR 审查、代码讨论）
- [ ] 确认构建、测试、部署流程不受影响

### 备用方案
- [ ] 保留旧工具的账号和配置至少 1 个月
- [ ] 准备一个备用工具（不同服务商），避免单一依赖
- [ ] 记录新工具的问题和限制，定期评估是否需要调整
- [ ] 关注工具的更新日志和政策变化
- [ ] 建立个人的工具评估标准，未来切换时复用

## 紧急情况处理

- 如果新工具出现严重问题，立即切回旧工具（确保旧工具仍可用）
- 如果遇到数据丢失，从备份中恢复配置和规则
- 如果遇到计费异常，立即联系客服并限制用量
- 如果遇到安全问题（密钥泄露等），立即轮换密钥并审计
