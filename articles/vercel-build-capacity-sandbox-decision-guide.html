Vercel 三处提速：64GB 构建磁盘、亚秒级沙箱快照与决策模型

2026年11月15日 11 分钟 作者：Avery Lin

11 月上旬 Vercel 连发几条更新：构建磁盘从 32GB 提到 64GB，Sandbox 快照中位创建时间从 4.4 秒降到 0.4 秒以内，AI Gateway 接入 Gemini Decision 1 直接输出布尔、选项与评分。三条更新分别对应构建、运行时与请求决策三个环节。这篇教程讲清各自的实际收益、边界与验收方法，避免把「容量变大」误当成「可以随便堆文件」。

来源与增量价值

本文基于官方资料整理，并补充适用场景、限制条件和实践检查步骤。

首要来源：Build disk space increased to 64 GB。事实以原始来源为准，本站建议需结合自己的环境验证。

构建失败有很多种，磁盘写满是最容易被误判成内存不足的一种；agent 慢也有很多种，环境恢复往往比模型推理更耗时；路由判断看似很轻，却经常被迫调用大模型生成一段 JSON。Vercel 这三条更新，正好各打中一个。

三条更新都不需要改配置：磁盘自动扩容、新快照自动用新格式、决策模型按调用计费。真正要做的不是「打开开关」，而是确认自己的项目能否吃到收益，以及边界在哪里。

这篇内容适合谁

  • 在 Vercel 上跑 monorepo、原生依赖或大型静态生成的开发者
  • 用 Sandbox 跑 agent 任务、关心冷启动的团队
  • 需要做请求路由、策略判断与工具过滤的 AI 应用开发者

实践与验证步骤

  • 确认当前构建失败是否与磁盘有关
  • 检查构建缓存与产物清理
  • 确认沙箱是否使用持久化模式
  • 评估存量快照是否需要重建
  • 选一个路由场景试用决策模型
  • 设置阈值与兜底逻辑
  • 观察日志与预算
  • 按验收清单核对

官方资料入口

  • Build disk space increased to 64 GB ：构建磁盘扩容范围
  • Sandbox snapshot creation up to 10x faster ：快照格式与恢复速度
  • Gemini Decision 1 on AI Gateway ：决策模型接口与模态
  • Speed Insights and Web Analytics custom environments ：自定义环境数据归属

重点判断与使用建议

  • 构建磁盘：32GB → 64GB，Basic 与 Standard 对齐 Enhanced/Turbo
  • 快照：中位创建 4.4s → 0.4s 以内，恢复 p50 500ms → 250ms
  • 决策模型调用名：google/gemini-decision-1
  • 决策调用计入日志与预算，不生成输出 token
  • 自定义环境：数据不再归到 Preview，历史数据不重算

一、三处提速分别解决什么

  • 构建磁盘：解决依赖与生成文件把磁盘写满导致的失败
  • 沙箱快照：解决每次任务开工前环境恢复太慢
  • 决策模型：解决路由与策略判断必须生成文本再解析的问题
  • 三者共同点是「不改变业务代码也能吃到收益」
  • 但都不是无限资源，边界比收益更值得先看

二、64GB 磁盘的实际收益

  • Basic 与 Standard 构建机从 32GB 提升到 64GB
  • Enhanced 与 Turbo 原本就是 64GB，现在四类机器持平
  • 适用于所有套餐与构建机类型，不额外收费
  • 不需要改配置，新构建自动生效
  • 对 monorepo、原生依赖、大型静态生成项目收益最明显

三、构建缓存与磁盘的边界

  • 磁盘变大不等于可以不做缓存清理
  • 构建缓存应只保留命中率高的目录，避免把旧产物越堆越多
  • 大文件不要进仓库，改用对象存储或构建时下载
  • 磁盘告警仍要监控，别等到再次写满才发现
  • 构建日志里要能区分「磁盘不足」与「内存不足」

四、Sandbox 快照为什么快了

  • 改用 Vercel Hive Snapshot（VHS）格式复用帧
  • 索引方式更高效，读写可以更多并行
  • 基础镜像与用户数据可以并行恢复
  • 中位创建时间从 4.4 秒降到 0.4 秒以内
  • 恢复 p50 从 500 毫秒降到 250 毫秒

五、VHS 格式与存量快照

  • 新快照自动使用新格式，无需配置
  • 已有快照保持旧格式，不会自动迁移
  • 想要提速的老项目需要重建一次快照
  • 持久化沙箱默认在会话结束时自动快照，下次从最新恢复
  • 快照不是备份，关键数据仍要落持久化存储

六、决策模型是什么

  • Gemini Decision 1 是多模态决策模型，不生成文本
  • 输出包括布尔概率、选项与评分
  • 可处理文本、图片、音频、视频与 PDF
  • 调用名 google/gemini-decision-1
  • 适合路由、策略判断、工具过滤与结果排序

七、用决策模型做路由

  • 把「是否转人工」「是否退款」「该调哪个工具」拆成独立问题
  • 为每个问题设置阈值，而不是只看概率最高的选项
  • 低置信度时走兜底：规则、人工或默认模型
  • 把决策结果与最终人工判断做对比，持续校准
  • 不要在决策模型里塞超长上下文，输入越长越难稳定

八、接口与模态限制

  • AI SDK 支持 PDF、音频、视频输入，需要 AI SDK 7
  • TypeSafe 兼容 API 与 Decisions API 只支持文本与图片
  • 决策调用会出现在日志里，并与普通请求一起计入预算
  • 不同接口的返回结构不同，封装时要统一成内部格式
  • 上线前用真实样本覆盖每种模态，别只测文本

九、成本与可观测

  • 决策模型按调用计费，不按输出 token 计费
  • 把决策调用单独打标签，避免和生成调用混在一个预算项
  • 记录每次决策的输入摘要、概率与最终动作
  • 定期抽样复核，防止阈值漂移导致错误路由
  • 自定义环境的数据归属已拆分，分析时注意历史口径

十、验收清单

  • 已确认构建失败是否由磁盘导致
  • 已清理低命中率缓存与大产物
  • 已确认沙箱使用持久化模式
  • 存量快照已评估是否重建
  • 已选一个路由场景完成决策模型对比
  • 阈值与兜底逻辑已写入代码
  • 决策调用已单独标记并纳入预算
  • 自定义环境报表口径已更新说明
