PHP2Shell · RCE

一、PHP 运行时两个未授权远程代码执行漏洞（CVE-2026-109618 / CVE-2026-109619）

来源：PHP 官方安全公告、The Hacker News、BleepingComputer，2026-10-21。

CVE-2026-109618 严重 · CVSS 9.2 未授权 RCE

1漏洞判断 / 类型

远程代码执行（RCE）。漏洞位于 PHP 运行时（引擎）本身，而非任何应用代码，因此即使站点自身代码安全、甚至只是一个 Hello World 页面，只要运行在受影响的 PHP 版本上就可能被攻击。官方将其与 CVE-2026-109619 合称为 PHP2Shell。

2漏洞成因

当一个请求异常结束时，PHP 可能把内存留在损坏状态。本漏洞利用一连串弱点触发内存溢出（Out-Of-Memory）导致的内存破坏，进而控制程序执行流。相关底层代码已存在于 PHP 中超过十年，影响范围可追溯到 PHP 5.4。

官方明确指出 mod_php（Apache）风险最高：已有可演示的利用，单个未授权请求在任何应用代码运行之前就能触发攻击。PHP-FPM 在请求早期失败时会关闭 worker，行为不同，但官方分析认为 FPM 仍可能受影响。

3利用方法 / 场景

  • 攻击者无需账号，通过构造的 HTTP 请求触发内存溢出损坏，以 Web worker 账户（如 www-data、apache）权限执行任意命令。
  • 影响所有处理 Web 请求的 PHP 部署：PHP-FPM、Apache mod_php、php-cgi、FrankenPHP、LiteSpeed。
  • 补丁发布前 Cloudflare 已观测到早期攻击尝试；WAF 规则只能临时拦截已知手法，不能替代补丁。
  • 研究人员（Wiz Research、Calif、OpenAI Codex 安全团队）指出，AI 模型帮助把这类长期存在的缺陷在约一周内转化为可工作的利用。

4修复方案

PHP 分支受影响版本首个修复版本
8.58.5.12 以下8.5.12
8.48.4.27 以下8.4.27
8.38.3.36 以下8.3.36
8.28.2.35 以下8.2.35

升级的是服务器上的 PHP 运行时，更新 WordPress、Laravel 等应用不会更新底层 PHP。升级后重启 Apache、PHP-FPM 及所有常驻 PHP worker。

无法立即升级时的临时缓解（不能彻底修复）：

; php.ini，禁止应用覆盖内存限制 memory_limit = -1 ; 保持 post_max_size 较低，并在 Web 服务器 / 代理层限制请求大小 post_max_size = 8M

注意：官方警告不要用 RLIMIT_AS / RLIMIT_DATA 替代，因为它们可能触发同样的漏洞路径。

CVE-2026-109619 严重 · CVSS 9.2 UAF / 内存泄露 / RCE

1漏洞判断 / 类型

过期全局状态（Stale Global State）导致的堆 Use-After-Free（释放后使用）、内存泄露与远程代码执行，同样无需授权。

2漏洞成因

请求异常结束后，PHP 全局状态未被正确清理，留下指向已释放内存的悬空引用，形成堆 Use-After-Free。攻击者可借此读取 PHP worker 进程内存，或进一步以 worker 权限执行代码。

3利用方法 / 场景

  • 内存读取：在拿到代码执行之前，攻击者就可读取 worker 内存，其中可能包含其他请求的密码、认证 token、API 密钥和证书；研究人员已在不控制目标应用的情况下演示读取实时 worker 内存。
  • 代码执行：官方确认该漏洞在 mod_php 和 PHP-FPM 上都可到达代码执行，但 FPM 路径依赖运行中应用内的某个操作。
  • 一条已确认的攻击路径与默认开启的 session 上传进度（session.upload_progress）有关，它能在 PHP 完成请求初始化前到达会话处理逻辑。

4修复方案

修复版本与 CVE-2026-109618 相同（8.5.12 / 8.4.27 / 8.3.36 / 8.2.35），升级后重启所有 worker。

无法立即升级时的临时缓解（仅阻断已确认的会话路径，不防御其他变体）：

; php.ini session.upload_progress.enabled = 0 ; PHP 8.5 还需关闭 fatal_error_backtraces = 0

官方强调：关闭 session 上传进度对 CVE-2026-109618 完全无效，且没有任何配置变更能在不升级的情况下彻底修复本漏洞。

老旧版本说明：PHP 8.1 及更早版本已不再由 PHP 项目提供更新，PHP 8.2 将于 2026 年 12 月 31 日 EOL。官方为 PHP 7.4、8.0、8.1 提供了最小化源码 backport；Linux 发行版 / LTS 厂商可能在旧版本号下打包了修复，应以软件包 changelog 中是否包含该 CVE 为准，而不是只看版本字符串。

Network Appliance

二、网络设备与安全产品漏洞（Citrix NetScaler / Fortinet FortiMail / Cisco NX-OS / Aruba AOS）

来源：Citrix 官方公告、FortiGuard PSIRT、NVD、CISA KEV。

CVE-2026-88779 高危 · 零日 CISA KEV

1漏洞判断 / 类型

Citrix NetScaler ADC 与 NetScaler Gateway 的 SAML 认证守护进程中，对内存缓冲区边界内操作的限制不当（CWE-119，缓冲区相关）。未授权远程攻击者可造成拒绝服务；RCE 风险在官方调查中，需持续关注公告。

2漏洞成因

当设备被配置为 SAML 服务提供方（SP）或 SAML 身份提供方（IdP）时，SAML 守护进程对特制请求的内存处理存在边界缺陷，处理畸形 SAML 数据可导致内存破坏 / 进程崩溃。

3利用方法 / 场景

  • 这是一个已被主动利用的零日漏洞，CISA 于 2026 年 10 月 4 日将其列入已知被利用漏洞（KEV）目录，要求联邦机构 10 月 7 日前完成修复。
  • 未授权攻击者发送特制 SAML 请求即可造成设备拒绝服务，影响 VPN / 应用发布可用性。
  • 仅在启用了 SAML（SP 或 IdP）配置的设备上可被利用。

4修复方案

部署形态修复版本
NetScaler ADC / Gateway 14.114.1-73.41 或更高
NetScaler ADC / Gateway 13.113.1-64.28 或更高
14.1-FIPS14.1-73.41 FIPS 或更高
13.1-FIPS / NDcPP13.1-37.282 或更高

无法立即升级时，可配置 Responder Policy 丢弃畸形 SAML 请求作为临时缓解，但升级固件才是彻底修复。修复后应检查设备日志中是否有早期被利用痕迹。

CVE-2026-104286 严重 · CVSS 9.8 未授权路径遍历

1漏洞判断 / 类型

Fortinet FortiMail 中对受限目录路径名的限制不当（CWE-22，路径遍历 / Path Traversal）。未授权攻击者可向受限目录之外写入文件，可能进一步导致代码执行或系统被控制。

2漏洞成因

FortiMail 某个功能在处理请求中的文件名 / 路径时，未正确过滤 ../ 等目录跳转字符，导致写入操作可逃逸出预期的受限目录，覆盖或落地任意文件。

3利用方法 / 场景

  • 未授权、无需用户交互，攻击向量为网络，CVSS 3.1 向量为 AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H（9.8 分）。
  • 受影响版本：FortiMail 8.0.0–8.0.1、7.6.0–7.6.6、7.4.0–7.4.8、7.2.0–7.2.9。
  • 该零日与针对 FortiGate / SSL VPN 的 FortiBleed 凭据泄露活动是不同事件，不应混为一谈。

4修复方案

FortiMail 分支受影响版本修复方案
8.08.0.0–8.0.1升级到 8.0.2 或更高
7.67.6.0–7.6.6升级到 8.0 修复分支
7.47.4.0–7.4.8升级到修复分支
7.27.2.0–7.2.9升级到 7.4 或更高

升级后检查是否存在异常写入的文件、Web 目录中的陌生脚本，并关注管理面是否暴露在公网；管理接口应尽量限制访问来源。

CVE-2026-76486 严重 · CVSS 9.8 未授权 root RCE

1漏洞判断 / 类型

栈基缓冲区溢出（CWE-121）导致的远程代码执行。Cisco NX-OS 软件的 VXLAN 运维管理特性（VXLAN OAM，又称 NGOAM）存在缺陷，未授权远程攻击者可以 root 权限执行任意代码，或造成设备拒绝服务。Cisco 给出的 CVSS 3.1 评分为 9.8，向量 AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H。

2漏洞成因

当 NGOAM 特性被启用时，设备对收到的 IP 流量没有做正确的输入校验。攻击者向受影响设备的 IP 接口发送构造数据包，畸形输入越过缓冲区边界、破坏栈上数据，进而劫持执行流；也可能使相关进程崩溃，引发设备重载。

3利用方法 / 场景

  • 攻击无需认证、无需用户交互，攻击者只要能把构造数据包送达受影响设备的 IP 接口即可。
  • 成功利用可直接获得 root 权限；未达成代码执行时，也常表现为进程崩溃、设备重载，造成业务中断。
  • 数据中心交换机、VXLAN 网络中启用了 NGOAM 的 NX-OS 设备受影响，涉及 9.3(3) 等多个版本，应以 Cisco 公告的受影响清单为准逐一核对。

4修复方案

按 Cisco 安全公告 cisco-sa-ngoam-rce-LWKQ4BU 升级到已修复的 NX-OS 版本。若业务不需要 NGOAM，应及时关闭该特性以缩小攻击面；对管理和数据接口实施访问控制，限制可向设备发送数据包的来源。修复后检查设备日志中的异常重载、畸形报文与陌生进程，确认是否曾被探测或利用。

CVE-2026-79879 高危 · CVSS 8.8 相邻网络 RCE

1漏洞判断 / 类型

内存损坏导致的远程代码执行。HPE ArubaOS（AOS-10）受影响接口存在内存损坏缺陷，未授权的相邻攻击者可在底层操作系统上以特权用户身份执行任意代码。HPE 给出的 CVSS 3.1 评分为 8.8，向量 AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H。

2漏洞成因

受影响接口在处理网络输入时存在内存损坏问题，攻击者从同一相邻网络（同一广播域 / 二层可达范围）发送构造请求，破坏内存布局并劫持控制流，最终以特权用户权限执行代码。

3利用方法 / 场景

  • 攻击向量为相邻网络（AV:A），攻击者无需认证、无需用户交互，但必须与目标设备二层可达。
  • 无线控制器、接入设备等 AOS-10 部署在内部网络被入侵后，可能被作为横向移动的跳板。
  • 受影响版本包括 AOS 10.8.0.0–10.8.1.1、10.7.0.0–10.7.2.6、10.4.0.0–10.4.1.13，应以 HPE 公告核对实际版本。

4修复方案

按 HPE Aruba 安全公告（hpesbnw05162en_us）升级到已修复版本。通过网络分段、隔离管理 VLAN 并限制管理接口访问来源，降低相邻攻击可达性；修复后检查设备日志中的异常请求与重启记录，确认是否存在早期入侵痕迹。

DevOps Platform & Security Gateway

三、协作平台与安全网关漏洞（GitLab / Sophos UTM）

来源：GitLab 官方公告、HackerOne、Sophos 安全公告、Ruby 官方、NVD。

CVE-2026-110264 严重 · CVSS 10.0 未授权 RCE

1漏洞判断 / 类型

GitLab 自托管实例（CE / EE）正则表达式编译器中的整数溢出，可导致未授权远程代码执行。漏洞由编译攻击者构造的正则表达式触发，CVSS 10.0 满分，无需登录、无需用户交互。

2漏洞成因

GitLab 用 Ruby 的 Regexp.new 编译用户提供的模式（如 CI 配置中的表达式）。特制模式在编译时使内部整数溢出（内部 ID 在大量重复时溢出），导致内存分配或指针错误，进而可被引导为代码执行。底层组件自 2014 年 7.0 版本起就存在于代码库，约十二年的自托管版本受影响。

关键区别：漏洞在编译期而非匹配期触发，因此 Regexp.timeout 无法防护，限制模式长度也不可靠（部分触发串很短）。

3利用方法 / 场景

  • 未授权攻击者提交构造的正则模式，Ruby 编译时整数溢出、内存破坏，以 GitLab 服务账户权限执行任意代码。
  • 影响范围：GitLab 7.0 以来所有自托管 CE / EE，直到各分支修复版本；GitLab.com 已修复，风险集中在自托管团队。
  • 同一名研究人员（joaxcar）约十天前还报告了 CI/CD 正则编译器的另一个满分 CVE-2026-97229。
  • 截至 10/28 未见确认的在野利用、未列入 CISA KEV，但 10/23-26 间已有复现材料流出，需警惕。

4修复方案

分支受影响至修复版本
19.519.5.019.5.1
19.419.4.219.4.3
19.319.3.519.3.6
19.2 / 19.1 / 19.0 / 18.11各分支修复前一版19.2.9 / 19.1.9 / 19.0.10 / 18.11.13

建议升级到 19.3.6 或更新，以同时获得同批另外 11 个安全修复；四个最老分支只回移了本关键补丁。其他编译用户可控正则的 Ruby 服务应升级到 Ruby 4.0.9、3.4.12 或 3.3.13（4.0.8 不包含本 CVE 修复）。修复后运行官方检测规则、排查 worker 崩溃日志，疑似失陷时轮换 CI/CD 变量、部署密钥与令牌。

CVE-2026-118633 严重 预认证 RCE · root

1漏洞判断 / 类型

Sophos UTM 中的路径遍历漏洞，可导致未授权远程攻击者在赢得竞态条件后以 root 权限执行任意命令。

2漏洞成因

当邮件代理（email proxy）启用扫描功能时，路径处理未正确过滤目录跳转字符，攻击者通过持续数分钟重复攻击赢得竞态条件，从而写入或执行文件并提权到 root。该漏洞由外部研究人员通过 Sophos 漏洞赏金计划报告。

3利用方法 / 场景

  • 未授权攻击者对启用邮件防护与扫描的 UTM 持续发起请求，利用竞态条件以 root 执行任意命令。
  • 影响所有 Sophos UTM 版本；UTM 已停止维护（end-of-life），补丁需手动安装。
  • 官方无临时缓解方案（Workaround: No），仍在使用 UTM 邮件防护的用户需尽快处理。

4修复方案

按官方补丁安装说明（KBA-000049692）手动安装补丁；长期建议迁移到受支持的 Sophos Firewall 版本。修复后检查邮件网关日志、异常进程与计划任务，确认是否存在被利用痕迹。

Remote Access & Collaboration

四、远程协作与访问工具漏洞（Collabora CODE Server / AnyDesk）

来源：NVD、MITRE、Nextcloud 官方帮助、AnyDesk 官方更新日志。

CVE-2026-110447 高危 · 在野利用 OS 命令注入

1漏洞判断 / 类型

OS 命令注入（CWE-78）导致的远程代码执行。受影响的是 Nextcloud 应用 Collabora Online Built-in CODE Server（richdocumentscode）26.4.303 之前版本，该漏洞在 2026 年 9 月至 10 月已被在野利用，与上一年的 CVE-2025-66208 是不同漏洞。

2漏洞成因

漏洞位于 proxy.php：当内置 CODE 服务没有运行时（例如产品刚被重启），代理脚本对用于拼接系统命令的输入未做正确过滤，攻击者可注入并执行任意操作系统命令。独立部署的 Collabora Online 服务器不存在该问题，只有这种内置 CODE Server 的部署形态受影响。

3利用方法 / 场景

  • 攻击者在 CODE 服务未运行的时间窗口，向 proxy.php 发送构造请求，注入命令并以服务账户权限执行。
  • 重启后、服务拉起前的窗口期是高风险时段，在野利用正集中针对这一状态。
  • 使用 Nextcloud 内置办公组件的个人站点和企业网盘均可能暴露，独立 Collabora 部署可排除。

4修复方案

将 richdocumentscode 升级到 26.4.303 或更高版本，并在 Nextcloud 应用管理中确认更新生效。修复后检查服务器日志中针对 proxy.php 的异常请求、异常进程与计划任务，确认是否已被利用；条件允许时改用独立部署的 Collabora Online，可规避内置 CODE Server 的同类风险。

CVE-2026-109390 严重 · CVSS 9.8 未授权 RCE · root

1漏洞判断 / 类型

堆缓冲区溢出（CWE-130，长度参数不一致）导致的未授权远程代码执行。AnyDesk 8.0.3 之前版本的远程攻击者无需受害者批准桌面控制，即可执行任意代码，在 Linux 上已演示以 root 权限执行命令。

2漏洞成因

会话协议中 mode 5 的流数据包处理器（stream packet handler）对载荷长度（payload length）字段没有做有效校验，攻击者提供异常长度值触发堆缓冲区溢出，进而破坏内存、劫持执行流。

3利用方法 / 场景

  • 攻击者主动发起会话，在协议层发送构造的 mode 5 数据包，利用长度校验缺陷完成堆溢出并提权。
  • 关键危害：无需用户点击“接受”或批准远程控制，攻击发生在交互授权之前。
  • 远程运维、办公环境中广泛部署 AnyDesk，暴露在公网或可被触达的主机风险最高。

4修复方案

升级到 AnyDesk 8.0.3 或更高版本，覆盖所有安装该客户端的终端并确认版本号。修复后排查异常会话日志与陌生进程；在管理策略上限制远程访问来源、关闭不必要的无人值守访问，并收敛远控工具的暴露面。

Web App & Remote Gateway

五、Web 应用与远程网关漏洞（WordPress / Ivanti Connect Secure）

来源：CISA KEV、WordPress 7.1.4 发布说明、Picus、BleepingComputer、Ivanti 公告、Volexity、Shadowserver。

CVE-2026-119977 高危 · CVSS 8.1 在野利用 · CISA KEV

1漏洞判断 / 类型

检查时间与使用时间不一致（TOCTOU）竞态条件（CWE-367），位于 WordPress 核心的完整包更新器。未授权远程攻击者在核心升级的短暂窗口内可访问本不应公开的临时文件，最终可导致远程代码执行。CVSS 3.1 评分 8.1，攻击复杂度高（需赢得时间竞态）；CISA 已于 11 月 3 日将其列入已知被利用漏洞目录，确认在野利用，要求联邦机构 11 月 6 日前修复。

2漏洞成因

核心更新流程是：下载安装包 → 解压到 wp-content/upgrade 下 → 校验 → 复制覆盖线上站点 → 删除临时目录。缺陷存在于解压与复制之间：临时目录位于公开 Web 根下、路径可预测，其中的 PHP 文件可被直接请求；临时安装器读不到线上的 wp-config.php，误判站点尚未安装，进而进入无需登录的安装流程，攻击者便可提交自己指定的数据库信息。

3利用方法 / 场景

  • 攻击者在更新窗口内访问可预测的临时安装路径，写入新的 wp-config.php，更新器随后把它复制覆盖线上配置。
  • 站点指向攻击者控制的空数据库后，攻击者创建首个管理员账号，再上传恶意插件执行任意 PHP。
  • 影响 WordPress Core 4.7 至 7.1.3，跨越近十年版本；7.1.4（10/28 发布）修复，旧分支以回移补丁形式提供。
  • 攻击复杂度高，但竞态可无限重试、目标可批量扫描，公开 PoC 传开后实际门槛会快速下降。

4修复方案

升级到 7.1.4 或对应分支的回移补丁；开启后台自动更新的站点会自动收到安全版本，WordPress.com 托管站点已更新、无需操作。无法立即升级时，在 Web 服务器拒绝访问 wp-content/upgrade 目录（nginx 用 location 规则返回 403，Apache 用 RedirectMatch 403），该缓解仅对本漏洞有效、需维持到升级完成。

排查失陷：在日志中搜索 wp-content/upgrade 下的 PHP（尤其 setup、install 端点）请求，检查 wp-config.php 的数据库配置改动、陌生管理员账号、未登记插件及 uploads 目录下异常 PHP；发现异常立即轮换数据库凭据、salts 和管理员密码。

CVE-2026-111357 / CVE-2026-118527 高危零日链 在野利用 · 提权 + 文件上传

1漏洞判断 / 类型

Ivanti Connect Secure（ICS）远程访问网关的两个漏洞，与认证绕过 CVE-2026-104935 串联成零日攻击链。CVE-2026-111357 是高危权限提升缺陷，CVE-2026-118527 允许已认证攻击者在未打补丁设备上上传文件。攻击者自 10 月 1 日起在野利用，安全厂商 Volexity 将其追踪为 UTA0576，可在设备上获得未授权 root 级代码执行。

2漏洞成因

10 月修复认证绕过 CVE-2026-104935 时，为尽快封堵主要利用路径，补丁优先解决主攻击面，而同一链条上的权限提升与文件上传两个缺陷当时仍在修复流程中。攻击者把三个漏洞串起来：先绕过认证，再利用提权缺陷、上传文件，最终以 root 执行命令。

3利用方法 / 场景

  • UTA0576 不部署恶意软件或 webshell，而是每执行一条命令就重新利用一次设备，并篡改日志掩盖痕迹，规避 Ivanti 完整性检查工具。
  • Shadowserver 追踪到全网超过 5000 台暴露在互联网的 ICS 实例，目前无法确认其中多少已完成修复。
  • CISA 已将 CVE-2026-104935 列入 KEV，并要求联邦机构在周五前完成修复。
  • 这类 VPN 网关是进入企业内网的快捷入口，历史上多次被用于零日攻击与勒索入侵。

4修复方案

按 Ivanti 更新公告安装覆盖 CVE-2026-111357 与 CVE-2026-118527 的补丁，确认设备是完整修复版本，而不仅是 10 月的认证绕过补丁。修复后运行完整性检查工具排查篡改，审查日志中的异常命令与重复利用痕迹；收敛管理接口的暴露范围和访问来源。由于攻击者不驻留文件，传统 webshell 查杀可能一无所获，应以日志和完整性检查为主。

System Service & Network Device

六、系统服务与网络设备漏洞（OpenSSH / Zyxel GS1900）

来源：NVD、腾讯云安全通告、Cloudflare Radar Zero Wire、Help Net Security、Binarly、GreyNoise、Zyxel 安全公告，2026-11-05 至 11-06。

CVE-2026-123158 高危 · CVSS 8.1 在野利用 · 9 小时内

1漏洞判断 / 类型

密码认证绕过（CWE-394，不当的错误处理），代号 *SSHole。影响 OpenSSH 10.6p2 之前的版本，触发条件三者同时满足：运行在 Linux、使用 musl libc、未启用 PAM。典型受影响环境包括 Alpine Linux、OpenWrt、Buildroot 与 Yocto，容器镜像与边缘设备尤其常见。

2漏洞成因

musl 的 crypt() 在密码长度超过 256 字节时，会把字符串 * 作为错误值返回。sshd 拿到这个 * 后与账户里存储的哈希字段比对，而部分账户的存储值同样是 *（表示该账户没有可用密码），两者相等，于是登录被判定为成功。在某些账户配置下，任意 256 至 1024 字符的密码都能通过验证。

利用还需要一个额外条件：机器上存在另一个使用 $5$ 或 $6$ 哈希的账户，sshd 会借用它的 salt 参与比对。只要有一个这样的账户，所有没有密码的账户就都变得可达。该缺陷自 2016 年起就存在，属于长期潜伏的错误处理问题，不是新引入的代码。

3利用方法 / 场景

  • 攻击者用超长密码尝试登录无密码账户，拿到 sshd 的普通用户会话，无需任何凭据。
  • Alpine 官方的 AWS 与 Azure 镜像中，默认 alpine 用户带免密 doas 权限，攻破后可直接获得 root，这也是本漏洞危害被抬高的主要原因。
  • Previdian 蜜罐记录到 CVE 公布后不到 9 小时的首个利用尝试，并在一台真实 Alpine Linux + OpenSSH 蜜罐上确认取得 root，来源 IP 为 89.116.89 段。
  • 受影响发行版覆盖面广，暴露在公网的 SSH 服务、CI 容器、网络设备管理面都属于高风险面。

4修复方案

升级到 OpenSSH 10.6p2 或更高版本，发行版用户以官方仓库的安全版本为准。无法立即升级时，优先启用 PAM，或关闭密码认证、改用密钥登录，并限制可不经 PAM 认证的账户范围；同时检查系统中是否存在使用 $5$/$6$ 哈希的账户，减少可被借用的 salt 来源。

排查失陷：检索 sshd 日志中长度异常密码的认证记录与来源 IP，核对是否出现陌生会话、doas/sudo 提权与新增公钥；容器镜像需重新构建而不是在运行实例里改配置。

CVE-2026-107441 高危零日 · 越界写 在野利用 · 补丁曾被绕过

1漏洞判断 / 类型

Zyxel GS1900 系列交换机固件 CGI 程序中的越界写（out-of-bounds write）。官方描述为局域网内未认证攻击者可通过特制 HTTP 请求执行操作系统命令，影响 GS1900-8、GS1900-8HP、GS1900-10HP、GS1900-24E 等共十个型号。

2漏洞成因

2026 年 6 月 Zyxel 修过一个栈溢出 CVE-2026-7273（影响 2.90(XXXX.1)C0 及更早，2.90(XXXX.2)C0 修复），该漏洞 9 月被列入 CISA KEV。但 Binarly 从攻击者服务器上取到名为 gs1900_bundle.tar.gz 的现成利用包，内含 PyArmor 混淆的 Python 脚本 exp.py，目标为 /cgi-bin/dispatcher.cgi。

测试发现，这个利用在已经打过 6 月补丁的全部十个固件版本上仍能未授权执行命令，说明攻击者依赖的并非 CVE-2026-7273，而是另一个缺陷——也就是 CVE-2026-107441。Patch 3 的修复方式是在复制数据前校验计数器，并对参数施加严格长度限制。

3利用方法 / 场景

  • 攻击者向交换机管理界面的 CGI 端点提交构造请求，无需账号即可执行命令。
  • GreyNoise 观测到同一攻击者入侵约 1000 台设备、覆盖 48 个国家，外泄配置文件、网络信息与 root 级哈希凭据。
  • Binarly 认为该利用很可能由大模型生成；防守方同样用模型搭建了可运行受影响固件的仿真环境来验证。
  • 管理界面暴露在公网、弱口令与默认配置会显著放大风险，即便官方公告写的是局域网条件。

4修复方案

升级到 2.90 Patch 3（(XXXX.3)C0），十个受影响型号逐一确认版本号；仅打 Patch 2 仍可被该利用绕过。修复后按「配置与凭据已外泄」处理：更换管理员口令与 root 凭据、核查配置文件是否被篡改、检查异常登录与流量；把交换机管理界面移出公网、限制管理来源网段。

这类案例的教训是公告与版本号不能盲信：打了补丁不等于修的是被利用的那个缺陷，评估时应结合厂商公告、实际利用报告与二进制层面的复核。

CISA KEV · 2026-11-09

七、AI 基础设施与通信平台漏洞（GPUStack / FreeSWITCH / IBM Aspera Faspex）

来源：CISA KEV 公告、厂商安全公告、The Hacker News、eSecurity Planet，2026-11-09 至 11-10。

CVE-2026-102895 严重 · CVSS 9.8 在野利用 · 已入 KEV

1漏洞判断 / 类型

不当认证（CWE-287），CVSS 9.8。影响 GPUStack 2.2.0 之前的版本，远程攻击者无需任何凭据即可获得管理员权限，属于典型的「认证边界被内部信任假设击穿」。GPUStack 是用于管理 GPU 集群与推理服务的平台，一旦失守，攻击面直接落到模型服务、云凭据与 worker 节点上。

2漏洞成因

应用会把远程请求误判为可信的本地流量：在特定反向代理配置下，或攻击者伪造 X-GPUStack-Real-IP 请求头时，来源判断被绕过，管理接口被当成内网本机调用。取得管理员能力后，攻击者可以创建管理员 API key、修改推理后端、读取云厂商凭据，并通过 POST /v2/inference-backends/from-yaml 在 worker 上执行命令。

厂商在公告中记录了一起真实攻击：一台 2.1.1 部署被植入恶意推理后端，进而反弹 shell。漏洞于 2026 年 7 月修复（公告 7 月 31 日），到 11 月 9 日进入 KEV，中间相隔约 101 天。

3利用方法 / 场景

  • 攻击者直接访问暴露在公网或跨网段可达的管理端口，伪造来源头后调用管理员接口。
  • 建立持久化管理员 API key，后续即使修补也不失效；这是升级后仍须人工吊销的原因。
  • 篡改推理后端配置，把流量引向恶意服务，或在 worker 上执行命令、横向到其他节点。
  • 读取 worker 与云厂商凭据，扩大到大模型服务、对象存储与集群管理面。
  • CISA 已确认在野利用，要求联邦机构在 11 月 12 日前完成修复并做取证 triage。

4修复方案

升级到 GPUStack 2.2.0 或更高版本。无法立即升级时，启用 force_auth_localhost=true，限制 API 访问来源，并在反向代理层禁止不可信客户端设置 X-GPUStack-Real-IP。

修复后必须按「可能已失陷」处理：审查管理员账号、API key、推理后端与 worker 配置，吊销未知或异常的管理员 key，轮换可能暴露的云与 worker 凭据。升级本身不会自动回收攻击者已创建的凭据，这一步不能省。

CVE-2026-116779 严重 · CVSS 9.8 在野利用 · 已入 KEV

1漏洞判断 / 类型

命令注入（CWE-78），CVSS 9.8，位于 SIP MESSAGE 处理路径。影响 FreeSWITCH 1.11.2 及更早版本，修复版本为 1.11.3。FreeSWITCH 广泛用于 PBX、呼叫中心与云通信平台，暴露 SIP 端口的实例是主要风险面。

2漏洞成因

SIP MESSAGE 中的内容没有被正确约束，特制消息可以触达应用内部的 API 命令接口，从而把「发一条消息」升级成「执行一条命令」。是否需要认证取决于 SIP profile 配置：部分场景下攻击者需要持有 SIP 账号，另一些配置下无需认证即可投递消息。SignalWire 已确认存在野外利用。

3利用方法 / 场景

  • 向暴露的 SIP 端口发送构造的 MESSAGE 请求，命中内部命令接口后执行系统命令。
  • 读取配置文件与凭据，获取 SIP 账号、上游 trunk 口令与数据库连接信息。
  • 任意控制通话：窃听、改路由、外呼欺诈，直接造成通信费用与数据泄露。
  • 以 FreeSWITCH 主机为跳板横向进入内网，呼叫中心与多云通信环境风险更高。
  • 仅依赖 SIP MESSAGE 认证并不能消除漏洞，官方明确要求升级。

4修复方案

升级到 FreeSWITCH 1.11.3 或更高版本。升级前后都要检查 SIP profile：确认 enable-chat-api-proto 处于关闭状态，业务不需要聊天能力时设置 enable-chat=false。

排查失陷：审查 SIP MESSAGE 流量与配置变更记录，检查异常进程、外连与新建账号；移除不必要的 SIP 账号，收敛暴露在公网的 profile，并对通话资费异常做对账。

CVE-2026-123218 严重 · CVSS 9.8 在野利用 · 已入 KEV

1漏洞判断 / 类型

授权不当导致的权限提升（CWE-863），CVSS 9.8。影响 IBM Aspera Faspex 5.0.0 至 5.0.19，修复版本为 5.0.19 PL1。成功利用可从普通用户提升到完全管理员权限，进而控制大文件传输平台与其中的业务数据。

2漏洞成因

已认证用户构造特定消息即可绕过授权检查，触发权限提升。IBM 公告描述为「需要已认证用户」，但其 CVSS 向量标注不需要权限，公告没有解释这一矛盾。防守方应按最坏情况评估：即使需要账号，弱口令、外包账号与泄露的凭据都能满足前置条件。

3利用方法 / 场景

  • 以低权限账号登录后发送构造消息，绕过授权成为管理员。
  • 读取与篡改传输中的大文件，媒体、影视后期、基因数据与供应链文件交换场景尤其敏感。
  • 新建高权限账号、修改传输策略与回调地址，把后续文件引流到攻击者控制端。
  • CISA 已确认在野利用，说明前置账号门槛并未阻止攻击者。

4修复方案

升级到 Faspex 5.0.19 PL1，并确认 faspex-core 容器镜像版本为 5.0.19 (1ce4b13, Fix Pack: 1)；只升应用不换镜像可能仍处于受影响状态。IBM 未提供 workaround，安全更新是唯一修复手段。

修复后审查管理员账号、权限变更与异常文件传输记录，排查新建的特权账号与被篡改的配置；对传输目录做完整性核对，必要时轮换与 Faspex 对接的凭据。
