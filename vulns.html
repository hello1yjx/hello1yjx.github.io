PHP2Shell · RCE

一、PHP 运行时两个未授权远程代码执行漏洞（CVE-2026-109618 / CVE-2026-109619）

来源：PHP 官方安全公告、The Hacker News、BleepingComputer，2026-10-21。

CVE-2026-109618 严重 · CVSS 9.2 未授权 RCE

1漏洞判断 / 类型

远程代码执行（RCE）。漏洞位于 PHP 运行时（引擎）本身，而非任何应用代码，因此即使站点自身代码安全、甚至只是一个 Hello World 页面，只要运行在受影响的 PHP 版本上就可能被攻击。官方将其与 CVE-2026-109619 合称为 PHP2Shell。

2漏洞成因

当一个请求异常结束时，PHP 可能把内存留在损坏状态。本漏洞利用一连串弱点触发内存溢出（Out-Of-Memory）导致的内存破坏，进而控制程序执行流。相关底层代码已存在于 PHP 中超过十年，影响范围可追溯到 PHP 5.4。

官方明确指出 mod_php（Apache）风险最高：已有可演示的利用，单个未授权请求在任何应用代码运行之前就能触发攻击。PHP-FPM 在请求早期失败时会关闭 worker，行为不同，但官方分析认为 FPM 仍可能受影响。

3利用方法 / 场景

  • 攻击者无需账号，通过构造的 HTTP 请求触发内存溢出损坏，以 Web worker 账户（如 www-data、apache）权限执行任意命令。
  • 影响所有处理 Web 请求的 PHP 部署：PHP-FPM、Apache mod_php、php-cgi、FrankenPHP、LiteSpeed。
  • 补丁发布前 Cloudflare 已观测到早期攻击尝试；WAF 规则只能临时拦截已知手法，不能替代补丁。
  • 研究人员（Wiz Research、Calif、OpenAI Codex 安全团队）指出，AI 模型帮助把这类长期存在的缺陷在约一周内转化为可工作的利用。

4修复方案

PHP 分支受影响版本首个修复版本
8.58.5.12 以下8.5.12
8.48.4.27 以下8.4.27
8.38.3.36 以下8.3.36
8.28.2.35 以下8.2.35

升级的是服务器上的 PHP 运行时，更新 WordPress、Laravel 等应用不会更新底层 PHP。升级后重启 Apache、PHP-FPM 及所有常驻 PHP worker。

无法立即升级时的临时缓解（不能彻底修复）：

; php.ini，禁止应用覆盖内存限制 memory_limit = -1 ; 保持 post_max_size 较低，并在 Web 服务器 / 代理层限制请求大小 post_max_size = 8M

注意：官方警告不要用 RLIMIT_AS / RLIMIT_DATA 替代，因为它们可能触发同样的漏洞路径。

CVE-2026-109619 严重 · CVSS 9.2 UAF / 内存泄露 / RCE

1漏洞判断 / 类型

过期全局状态（Stale Global State）导致的堆 Use-After-Free（释放后使用）、内存泄露与远程代码执行，同样无需授权。

2漏洞成因

请求异常结束后，PHP 全局状态未被正确清理，留下指向已释放内存的悬空引用，形成堆 Use-After-Free。攻击者可借此读取 PHP worker 进程内存，或进一步以 worker 权限执行代码。

3利用方法 / 场景

  • 内存读取：在拿到代码执行之前，攻击者就可读取 worker 内存，其中可能包含其他请求的密码、认证 token、API 密钥和证书；研究人员已在不控制目标应用的情况下演示读取实时 worker 内存。
  • 代码执行：官方确认该漏洞在 mod_php 和 PHP-FPM 上都可到达代码执行，但 FPM 路径依赖运行中应用内的某个操作。
  • 一条已确认的攻击路径与默认开启的 session 上传进度（session.upload_progress）有关，它能在 PHP 完成请求初始化前到达会话处理逻辑。

4修复方案

修复版本与 CVE-2026-109618 相同（8.5.12 / 8.4.27 / 8.3.36 / 8.2.35），升级后重启所有 worker。

无法立即升级时的临时缓解（仅阻断已确认的会话路径，不防御其他变体）：

; php.ini session.upload_progress.enabled = 0 ; PHP 8.5 还需关闭 fatal_error_backtraces = 0

官方强调：关闭 session 上传进度对 CVE-2026-109618 完全无效，且没有任何配置变更能在不升级的情况下彻底修复本漏洞。

老旧版本说明：PHP 8.1 及更早版本已不再由 PHP 项目提供更新，PHP 8.2 将于 2026 年 12 月 31 日 EOL。官方为 PHP 7.4、8.0、8.1 提供了最小化源码 backport；Linux 发行版 / LTS 厂商可能在旧版本号下打包了修复，应以软件包 changelog 中是否包含该 CVE 为准，而不是只看版本字符串。

Network Appliance

二、网络设备与安全产品漏洞（Citrix NetScaler / Fortinet FortiMail）

来源：Citrix 官方公告、FortiGuard PSIRT、NVD、CISA KEV。

CVE-2026-88779 高危 · 零日 CISA KEV

1漏洞判断 / 类型

Citrix NetScaler ADC 与 NetScaler Gateway 的 SAML 认证守护进程中，对内存缓冲区边界内操作的限制不当（CWE-119，缓冲区相关）。未授权远程攻击者可造成拒绝服务；RCE 风险在官方调查中，需持续关注公告。

2漏洞成因

当设备被配置为 SAML 服务提供方（SP）或 SAML 身份提供方（IdP）时，SAML 守护进程对特制请求的内存处理存在边界缺陷，处理畸形 SAML 数据可导致内存破坏 / 进程崩溃。

3利用方法 / 场景

  • 这是一个已被主动利用的零日漏洞，CISA 于 2026 年 10 月 4 日将其列入已知被利用漏洞（KEV）目录，要求联邦机构 10 月 7 日前完成修复。
  • 未授权攻击者发送特制 SAML 请求即可造成设备拒绝服务，影响 VPN / 应用发布可用性。
  • 仅在启用了 SAML（SP 或 IdP）配置的设备上可被利用。

4修复方案

部署形态修复版本
NetScaler ADC / Gateway 14.114.1-73.41 或更高
NetScaler ADC / Gateway 13.113.1-64.28 或更高
14.1-FIPS14.1-73.41 FIPS 或更高
13.1-FIPS / NDcPP13.1-37.282 或更高

无法立即升级时，可配置 Responder Policy 丢弃畸形 SAML 请求作为临时缓解，但升级固件才是彻底修复。修复后应检查设备日志中是否有早期被利用痕迹。

CVE-2026-104286 严重 · CVSS 9.8 未授权路径遍历

1漏洞判断 / 类型

Fortinet FortiMail 中对受限目录路径名的限制不当（CWE-22，路径遍历 / Path Traversal）。未授权攻击者可向受限目录之外写入文件，可能进一步导致代码执行或系统被控制。

2漏洞成因

FortiMail 某个功能在处理请求中的文件名 / 路径时，未正确过滤 ../ 等目录跳转字符，导致写入操作可逃逸出预期的受限目录，覆盖或落地任意文件。

3利用方法 / 场景

  • 未授权、无需用户交互，攻击向量为网络，CVSS 3.1 向量为 AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H（9.8 分）。
  • 受影响版本：FortiMail 8.0.0–8.0.1、7.6.0–7.6.6、7.4.0–7.4.8、7.2.0–7.2.9。
  • 该零日与针对 FortiGate / SSL VPN 的 FortiBleed 凭据泄露活动是不同事件，不应混为一谈。

4修复方案

FortiMail 分支受影响版本修复方案
8.08.0.0–8.0.1升级到 8.0.2 或更高
7.67.6.0–7.6.6升级到 8.0 修复分支
7.47.4.0–7.4.8升级到修复分支
7.27.2.0–7.2.9升级到 7.4 或更高

升级后检查是否存在异常写入的文件、Web 目录中的陌生脚本，并关注管理面是否暴露在公网；管理接口应尽量限制访问来源。
