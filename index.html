GitHub Changelog 2026年11月23日

代码覆盖率上传开始校验报告格式：不是 Cobertura XML 直接失败并报明确错误

GitHub Code Quality 的 upload-code-coverage action 现在会检查覆盖率报告是否为 Cobertura XML 格式；格式不被支持时上传步骤直接失败，Actions 日志给出明确提示，要求换成 Cobertura XML 或在上传前转换。过去这类上传看似成功，但 PR 上不会显示覆盖率。对合法 Cobertura 报告也放宽了容错：轻微结构问题不再整体拒收，缺少可用行号或命中次数的个别行会被跳过，而不是丢弃整份报告。该能力需要仓库开启 GitHub Code Quality，目前面向 GitHub Enterprise Cloud 与 GitHub Team（含数据驻留），GHES 暂不可用。

把「代码覆盖率上传开始校验报告格式：不是 Cobertura XML 直接失败并报明确错误」变成一个可验证动作

不追热点名词，先学会核对来源、判断影响范围，再在自己的工具或项目里完成一个低风险检查。

  1. 打开一手来源，只记录发布日期、影响对象和需要核对的配置。
  2. 用 AI 工具来源核验表检查权限、数据边界、费用或模型依赖。
  3. 在自己的项目里做一次只读验证，例如查看默认模型、配置项或日志。
  4. 写下结论：继续使用、暂缓使用，或需要回滚到原方案。
