GitHub Changelog 2026年11月20日

安全公告权限正式可用：自定义仓库角色就能处理漏洞报告，不必再给管理员

GitHub 把安全公告权限从预览转为正式可用。组织所有者现在可以通过自定义仓库角色，让人处理仓库安全公告与私密漏洞报告，不再需要授予仓库管理员或组织级 security manager。Security 分类下新增四项权限：查看安全公告；创建、编辑与管理安全公告（含评论、协作者管理、创建临时私有 fork）；接收私密漏洞报告并关闭或重开公告；发布公告并申请 CVE。后两项都要求先具备前两项之一。角色可以只分配到需要的仓库上。限制也要记清：合并临时私有 fork 的改动仍需仓库管理员或 security manager；拥有这些新权限的人不能删除临时私有 fork；机密评论只对同时具备管理权限与仓库写权限的人开放。

Vercel Changelog 2026年11月20日

Vercel Functions 请求体上限提到 20MiB：需要显式开启，中间件将拿不到 body

Vercel Functions 的入站请求体上限从 4.5MB 提升到 20MiB，处于公开测试。开启方式是设置环境变量 VERCEL_SUPPORT_LARGE_REQUEST_BODY=1，按项目、按环境生效，可以先在 preview 验证再上生产。前提是项目的函数使用 4GB 性能内存档位，适用于 Node.js、Python、Bun 运行时与 Routing Middleware。Edge 运行时的函数与中间件仍保持 4.5MB 上限，超限返回 413，要享受新上限需切到 Node.js 运行时（runtime 设为 nodejs，或 Next.js 的 proxy.ts）。项目一旦开启，Routing Middleware 只收到请求头与元数据、不再收到请求体，这是项目级强制行为，目的是避免把 body 同时发给中间件和目标函数而抬高成本与首字节时间。

CISA Alert 2026年11月20日

CISA 再收录四个在野利用漏洞，并按 BOD 26-04 改为风险优先级修复

CISA 于 11 月 20 日向 KEV 目录新增四个漏洞：SAP NetWeaver 数据查询逻辑特殊元素中和不当（CVE-2025-42884）、Cisco Expressway 系列硬编码凭据（CVE-2026-76466）、VMware vCenter 备用路径认证绕过（CVE-2026-123890）、Apache Roller 不可信数据反序列化（CVE-2026-129448）。同份公告说明，联邦机构的漏洞管理要求已改由 BOD 26-04《基于风险确定安全更新优先级》承接：优先快速修复 KEV 中、位于公开暴露资产且利用后可完全控制资产的漏洞，较低风险的可延后；同时明确了「必须检查补丁前是否已被入侵」的基本预期。BOD 26-04 只约束联邦文职行政机构，CISA 建议其他组织同样采用基于风险的漏洞管理。

今天 10 分钟能学什么

把「安全公告权限正式可用：自定义仓库角色就能处理漏洞报告，不必再给管理员」变成一个可验证动作

不追热点名词，先学会核对来源、判断影响范围，再在自己的工具或项目里完成一个低风险检查。

  1. 打开一手来源，只记录发布日期、影响对象和需要核对的配置。
  2. 用 AI 工具来源核验表检查权限、数据边界、费用或模型依赖。
  3. 在自己的项目里做一次只读验证，例如查看默认模型、配置项或日志。
  4. 写下结论：继续使用、暂缓使用，或需要回滚到原方案。
