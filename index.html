GitHub Changelog 2026年11月24日

GitHub 通知行为改为更可预测：12 月 1 日起分批迁移，常规操作不再自动重订阅

从 2026 年 12 月 1 日起，GitHub.com 用约一周时间分批迁移通知逻辑，目标是让订阅更可预测、修正异常行为并支撑更大规模的活动量。迁移期间不同用户可能看到不同表现，不需要手动操作，GHES 不受影响。主要变化：手动取消订阅后，评论、提交评审、改变线程状态、合并队列活动等常规动作不再把你重新订阅，只有被提及、被指派、被请求评审才会重新订阅；团队提及通知按当前成员关系计算，退出团队或移除提及后不再收到后续通知；Subscriptions 页面只列手动订阅的线程，其余通知要到收件箱管理；收件箱与邮件页脚显示的原因改为固定优先级，依次为提及、团队提及、指派、请求评审、评论、手动、作者、状态变更、订阅，Issue 场景下指派优先级最高；邮件头会带上全部适用原因。

项目管理
GitHub Changelog 2026年11月23日

Issue 状态与仓库看板进入公开预览：七种状态可自动流转

GitHub 为 Issue 增加七种状态：Backlog、Todo、In progress、In review、Done、Not planned、Duplicate，可在创建时选择或在 Issue 头部修改，仓库 Issue 列表、Issue 仪表盘与仓库看板都会显示对应图标，并支持用 status: 过滤。状态会自动流转：把草稿 PR 关联到 Issue 会移到 In progress；草稿 PR 标记为 Ready for review 会移到 In review；关联已打开的 PR 会移到 In review；给 Issue 指派用户会移到 Todo；指派 agent 会移到 In progress；如果 GitHub Project 里有同名状态值，两边任一改动会同步。GraphQL、REST API 与 MCP server 都支持读写状态与创建时指定初始状态，状态变更也可作为 Copilot 自动化的触发条件。仓库保存视图新增看板布局，可按状态分组、拖拽改状态，并配置列、泳道、可见字段与排序。Issue 字段也不再强制绑定 Issue 类型。

今天 10 分钟能学什么

把「Copilot 代码评审计费默认改到组织：12 月 30 日起未设置的组织统一承担」变成一个可验证动作

不追热点名词，先学会核对来源、判断影响范围，再在自己的工具或项目里完成一个低风险检查。

  1. 打开一手来源，只记录发布日期、影响对象和需要核对的配置。
  2. 用 AI 工具来源核验表检查权限、数据边界、费用或模型依赖。
  3. 在自己的项目里做一次只读验证，例如查看默认模型、配置项或日志。
  4. 写下结论：继续使用、暂缓使用，或需要回滚到原方案。
